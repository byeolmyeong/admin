# 004. 서버 경로가 아직 없는 구역은 환경 변수로 숨긴다

> 상태: 활성 · 결정일 2026-11-20 · 003 의 메뉴 묶음 넷(여덟 구역)은 그대로 — 운영에서만 일부를 잠시 뺀다

## 맥락
- 어드민 main 은 운영(admin.byeolmyeong.com)이고 운영 API(서버 main)를 부른다. develop 은 서버 develop 을 부른다.
- 사용자(서버 S⑪) · 푸시 발송(서버 S10-5) 경로는 운영 서버에 아직 없다. 그대로 열면 "불러오지 못했습니다" 화면과 누르면 404 인 버튼이 운영에 보인다.
- 소유자(2026-11-20): 서버 S⑪ · S10-5 가 운영에 나올 때까지 운영 어드민에서 사용자 · 푸시 발송 메뉴를 숨긴다. 기본은 보이기, 운영 Vercel 에서만 숨김 값.

## 결정
- 환경 변수 `VITE_HIDDEN_SECTIONS`(쉼표로 나눈 구역 이름, 예 `users,push`). 비우면 모두 보인다.
- 숨긴 구역은 메뉴(데스크톱 · 아이콘 띠 · 폰 서랍)와 라우트에서 빠진다. 그 주소(`/users` · `/push` 와 그 아래)는 첫 구역(현황)으로 보낸다(`src/app/sections.tsx` 의 `visibleSections`).
- 다른 화면이 숨긴 구역으로 가는 링크는 그리지 않고 글로만 둔다(`isSectionShown`). 지금은 문의 상세 작성자 줄의 "사용자 상세 ›" 하나다.
- 감사 로그의 "이 계정만 보기"는 감사 로그 안의 거르기(운영 서버에도 있는 `actorRef`)라 그대로 둔다.

## 버린 대안
- 코드의 `hidden` 을 다시 켜기 — 운영과 develop 이 갈라져 develop 에서 화면을 볼 수 없다.
- 운영 서버에 맞춘 두 갈래 화면 — 곧 지울 코드가 생긴다.

## 영향
- 운영 Vercel 의 `VITE_HIDDEN_SECTIONS=users,push` 를 넣고 다시 빌드해야 적용된다(빌드 때 들어가는 값). 서버 S⑪ · S10-5 가 운영에 나오면 값을 지우고 다시 빌드한다.
